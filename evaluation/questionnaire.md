# Usability questionnaire (Part B)

Give this to each participant AFTER they finish the tasks. Record answers in
`usability_responses.csv` (one row per participant). Scale for every item:
1 = strongly disagree ... 5 = strongly agree.

## System Usability Scale (Brooke, 1996) - standard 10 items

| Col | Statement |
|---|---|
| sus_1 | I think that I would like to use this system frequently. |
| sus_2 | I found the system unnecessarily complex. |
| sus_3 | I thought the system was easy to use. |
| sus_4 | I think that I would need the support of a technical person to be able to use this system. |
| sus_5 | I found the various functions in this system were well integrated. |
| sus_6 | I thought there was too much inconsistency in this system. |
| sus_7 | I would imagine that most people would learn to use this system very quickly. |
| sus_8 | I found the system very cumbersome to use. |
| sus_9 | I felt very confident using the system. |
| sus_10 | I needed to learn a lot of things before I could get going with this system. |

(If participants prefer Indonesian, translate the items consistently and say
in the report that the translation was not formally validated.)

## Project-specific items (1-5)

| Col | Statement |
|---|---|
| usefulness_1_5 | The recognised text would be useful for my own notes. |
| text_quality_1_5 | The recognised text was accurate enough to read without the photo. |
| would_use_for_notes_1_5 | I would use this tool to digitise handwritten notes. |
| trust_in_output_1_5 | I would trust the output without checking it. |

`tasks_completed`: how many of the tasks in PROTOCOL.md Part B the participant
completed without help (e.g. `3/4`). `comments`: free text, verbatim.

## Open questions (record verbatim in `comments`)

1. What went wrong, if anything?
2. What kind of handwriting or photo did the tool handle worst?
3. What would you need before using it for real lecture notes?
